현장 정보 플랫폼
Beta 1 주요 사용자 기능 정리
작성일: 2026-08-21

1. Beta 1 목적
- 핵심 검증 목표: "현장에 있는 사용자가 정보를 제공하고, 그 정보를 원하는 사용자가 실제로 소비하는가?"
- 모든 사용자는 Requester와 Provider 역할을 모두 수행할 수 있음.

2. 회원 / 프로필
- 회원가입
- 로그인 / 로그아웃
- 닉네임 설정
- 관심 카테고리 설정
- 사용자 프로필 조회
- 내 활동내역 조회
- Provider 기본 신뢰도 표시
- 초기 신뢰 등급: NEW / NORMAL / TRUSTED

3. 지도 / 장소 검색
- 현재 위치 표시
- 장소명 검색
- 지도에서 장소 선택
- 주변 LIVE 조회
- 주변 REQUEST 조회
- Information Topic 조회
- Place Timeline 조회
- 국내 대상 위치: NAVER Maps
- 해외 대상 위치: Google Maps
- 지도 선택은 사용자의 국적이 아니라 대상 장소 국가 기준

4. 장소 화면
- 최근 현장정보
- LIVE 정보
- REQUEST 결과
- 진행 중 REQUEST
- 정보 최신시간
- 카테고리별 Timeline
- [현재 정보 요청] 연결

5. 무료 LIVE 정보 조회
- 장소
- 카테고리
- 현재 상황
- 설명
- 사진
- 관찰 시각
- Information Age
- 위치 확인 여부
- 도움됨 수
- 복수 사용자 확인 여부
- 사용자 행동: 도움됨 / 상황 변경됨 / 신고

6. LIVE 현장정보 등록
- 현재 위치
- 장소
- 카테고리
- 상황 설명
- 사진
- 관찰 시각
- 등록된 LIVE는 다른 사용자에게 무료 정보로 제공

7. 현장정보 REQUEST 생성
- 장소
- 세부 위치 또는 Zone
- 요청 제목
- 확인 질문
- 필요한 사진 수
- 완료 제한시간
- 보상 Point
- 공유 여부
- SHARED / PRIVATE

8. REQUEST 생성 전 기존정보 확인
우선순위:
1) 최신 무료 LIVE
2) 최근 REQUEST 결과
3) 진행 중 공동 REQUEST
4) 신규 REQUEST

선택:
- [무료 LIVE 보기]
- [기존 정보 Point로 보기]
- [공동 요청 참여]
- [그래도 새 요청]

9. 기존 현장정보 재열람
- TTL 내 최근 REQUEST 결과를 낮은 Point로 재사용
- Beta 1은 고정 재열람 Point 사용
- TTL이 만료된 정보는 최신 정보처럼 유료 판매하지 않음

10. 공동 REQUEST 참여
- 동일 Place / Topic의 진행 중 REQUEST가 있으면 공동 참여 제안
- 참여자 Point가 Pool에 누적
- Beta 1에서는 Provider 기본 1명
- 결과가 생성되면 참여자 모두 열람 가능

11. 주변 REQUEST 탐색
- 지도에서 주변 REQUEST 확인
- 앱 사용 중 주변 REQUEST 알림
- 관심 카테고리 기반 요청 확인
- 요청 상세: 장소 / 거리 / 요청내용 / 필수항목 / 사진 수 / 남은시간 / 보상 Point

12. REQUEST 수행 수락
- [수행하기]
- Beta 1 수행 유형:
  - LOCAL: 이미 현장 또는 현장 주변에 있는 사용자
  - FIELD: 요청 수행을 위해 이동하는 사용자
- 기본 원칙: LOCAL First / FIELD Second

13. 현장 수행 / 결과 제출
- 현장 GPS 확인
- 요청 위치와 거리 확인
- 질문별 답변
- App Camera로 사진 촬영
- 필수 사진 수 확인
- 촬영시각 기록
- 결과 제출
- 제출 전 검증: 필수 질문 / 사진 수 / GPS / 촬영시간

14. 사진 보호
- 원본 사진 비공개 저장
- 서비스 표시용 이미지 별도 생성
- Visible Watermark 적용
- EXIF 민감정보 제거
- Evidence ID 부여
- File Hash 저장
- 일반 사용자는 원본 Storage 파일에 직접 접근하지 않음
- 목적: 복제 억제 + 출처 추적 + 원본 보호

15. 요청 결과 확인
- 확인 시각
- 질문별 답변
- 현장 사진
- Provider 신뢰 등급
- GPS 인증 여부
- 위치 검증 결과
- 사용자 행동: [문제없음] / [이의제기]
- Review Window 동안 문제 없으면 자동 승인

16. Point
- Beta 1에서는 실제 결제 미사용
- 서비스 Beta Point 사용
예:
- 신규 가입 +50,000P
- REQUEST 생성 -5,000P HOLD
- Provider 정상 완료 +5,000P
- 기존 정보 열람 -1,000P
- 사용자 확인: 사용 가능 Point / HOLD Point / 거래내역
- Beta Point는 현금 교환 불가

17. 알림
- 현재 위치 주변 REQUEST 발생
- 내가 등록한 REQUEST 수락
- Provider 결과 도착
- 공동 REQUEST 결과 도착
- Point 지급
- REQUEST 만료
- LIVE 알림은 REQUEST보다 보수적으로 운영

18. 신고 / 정보 상태 변경
신고 사유 예:
- 허위정보
- 오래된 정보
- 상황 변경됨
- 개인정보
- 부적절한 사진
- 위험한 요청
- 촬영금지 장소
- 광고 / 스팸
- 기타
중요:
- "상황 변경됨"은 "허위정보"와 분리
- 등록 당시 사실이었으나 이후 상태가 변한 경우 Provider 패널티 없음

19. Place Timeline
- 장소의 현장정보를 시간순으로 확인
- LIVE와 REQUEST RESULT를 함께 표시
- 과거 정보를 덮어쓰지 않고 변화 이력으로 보존

20. Information Topic
- 같은 장소의 유사 LIVE / REQUEST를 묶어 중복 표시와 중복 수행을 줄임
- Beta 기준: Place + Zone + Category + Time Window

21. LIVE 폭주 대응
- 유사 LIVE 대량 등록 시 하나의 Topic/Event로 묶음
- 현장 제보 수, 최근 확인 시각, 대표 사진, 복수 사용자 확인을 표시
- 여러 사용자의 동일 제보는 Crowd Verification 신호로 활용

22. REQUEST 폭주 대응
- 동일 정보 REQUEST가 많으면 공동 REQUEST 참여를 우선 제안
- 불필요한 중복 수행 감소
- Provider 효율 향상
- 동일 정보 수요 확인
- Point Pool 형성

23. 사용자 신뢰도
- 정상 완료 REQUEST 수
- 승인율
- 평점
- 분쟁 수
- 신고 수
- GPS 인증률
- 초기 공개 등급: NEW / NORMAL / TRUSTED

24. 지역 명성 / 지역 칭호
- 사용자가 특정 생활반경에서 유용한 정보를 지속적으로 제공하면 장소별 Local Reputation 축적
- Beta 1에서는 데이터만 수집
- 향후 예:
  - 보라매공원 호수의 관찰자
  - 보라매공원 호수의 파수꾼
  - 보라매공원 호수의 지배자
  - 안양천 합수부의 관찰자
- 단순 방문 횟수가 아니라 유효한 정보 기여 기준

28. Beta 1 핵심 검증 지표
Requester:
- 장소 검색 수
- LIVE 열람률
- 기존정보 재사용률
- 공동 REQUEST 참여율
- 신규 REQUEST 생성률

Provider:
- 주변 REQUEST Push 열람률
- REQUEST 상세 진입률
- 수락률
- 정상 완료율
- 평균 수행시간

서비스 핵심:
- LOCAL Fulfillment Rate
- 현장정보 재사용률
- LIVE 유효정보 비율
- 신고 / 분쟁률
- 사용자 재방문율

29. Beta 1 핵심 가치
무료 정보가 있으면 무료로 본다.
최근 확인된 정보가 있으면 재사용한다.
누군가 이미 요청 중이면 같이 참여한다.
그래도 필요한 정보가 없으면 현장 사용자에게 새롭게 요청한다.
생성된 정보는 다시 Place Timeline과 Information Topic의 최신 현장정보 자산으로 축적된다.
